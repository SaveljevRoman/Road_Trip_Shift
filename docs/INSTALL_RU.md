# Установка Road Trip Shift

Версия **0.3.2 — экспериментальная**. Эта инструкция также вложена в ZIP. В репозитории: [Описание проекта](../README_RU.md) · [На английском](INSTALL.md).

## Требования

Windows x64 и Road Trip: Ford. Проверено на ATS **1.62.1.1**. Адреса кода находятся автоматически по сигнатурам инструкций; ограничений по версии или хешу EXE нет. Другие сборки игры пока не проверены. Мультиплеер не проверен. Базовое поведение проверялось с 0.2.2; новая защита круиза в 0.3.1 ещё требует проверки в поездке. Новый клавиатурный ввод газа и поиск адресов также ещё требуют проверки в поездке.

## Ручная установка

1. Закройте ATS обычным способом. Скачайте и распакуйте установочный ZIP; сам архив в `mod` не копируется.
2. В Steam выберите ATS → Управление → Просмотреть локальные файлы. Откроется `path_to_game`.
3. Скопируйте папку `bin` из архива в каталог игры с объединением папок. При необходимости создайте `plugins`. Должно получиться:

```text
path_to_game/
  bin/win_x64/
    amtrucks.exe
    plugins/
      road_trip_shift.dll
      road_trip_shift/
        road_trip_shift.ini
```

Для работы достаточно DLL: без INI используются встроенные значения. При обновлении сохраните существующий INI. При распространении сохраняйте папку `licenses` из ZIP. Библиотеки среды выполнения компилятора встроены статически; дополнительные DLL компилятора не требуются.

4. Запустите ATS и подтвердите использование SDK. Выберите поддерживаемый Ford, автоматическую коробку и нужный режим адаптивных переключений. Для клавиатурного разгона двойным нажатием газа используется штатная функция полного газа при двойном нажатии. Плагин автоматически следует назначению газа в ATS; отдельная настройка клавиши не нужна.

Активация через менеджер модов для DLL не нужна. `amtrucks.exe` заменять не требуется.

## Необязательный установщик PowerShell

Из каталога распакованного ZIP, в PowerShell 7:

```powershell
pwsh -File ./Install.ps1 -GameRoot 'path_to_game'
```

Установщик откажется работать при запущенной игре, сверит хеш DLL, сохранит предыдущую DLL и существующий INI. Файл `installation.json` с информацией об установке и резервные копии находятся в `plugins/road_trip_shift/`. Профили и другие плагины он не меняет.

## Настройки

При закрытой ATS отредактируйте `bin/win_x64/plugins/road_trip_shift/road_trip_shift.ini`, затем перезапустите игру:

| Секция / ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `plugin / enabled` | `1` | `0` отключает поведение плагина |
| `input / double_tap_ms` | `300` | Интервал между нажатиями, мс; ограничен 100–700 |
| `input / analog_kickdown` | `1` | Аналоговый кикдаун двойным нажатием педали/курка, как в main |
| `input / controls_file` | пусто | Необязательный путь к controls.sii; пустое значение включает поиск активного профиля |
| `cruise / normal_acceleration` | `1` | Normal при отставании больше 3 км/ч; удержание до цели, отмена при вмешательстве |
| `cruise / anti_hunt` | `1` | `0` отключает новую защиту круиза для сравнения |
| `logging / enabled` | `1` | `0` отключает запись диагностических файлов, обновление состояния и сообщения плагина в игровом логе |
| `logging / max_total_mb` | `50` | Общий лимит логов событий и таблиц телеметрии в МиБ; ограничен 1–1024 |
| `logging / sample_ms` | `200` | Интервал телеметрии, мс; ограничен 100–2000 |

Кикдаун следует клавиатурному назначению газа из controls.sii активного профиля; жёсткой привязки к W нет. Распознавание двойного нажатия, удержания, отпускания и отмены после паузы/тормоза оставлено из main. Свежий SDK-ввод записывается для диагностики, но не подтверждает и не блокирует клавиатурное нажатие. Подтверждение каждого нажатия с учётом нарастания «умного газа» отложено в [план реализации](IMPLEMENTATION_PLAN.md). Аналоговый кикдаун из main сохранён: два нажатия педали/курка временно включают High Power; отключение — input/analog_kickdown=0. Плагин не подставляет полный аналоговый газ. Интервал двойного нажатия по умолчанию — 300 мс.

Плагин читает `mix dforward` из `controls.sii` активного профиля. Поддерживаются буквы, цифры основного ряда, F1–F12, стрелки, пробел, Tab, Backspace, Esc, отдельные Shift/Ctrl/Alt, клавиши навигации и основные знаки пунктуации. Поддерживаются простые альтернативные назначения через OR; варианты от контроллера игнорируются. Сложные выражения, сочетания через AND, неизвестные имена клавиш, Enter и цифровой блок не поддерживаются: их физические варианты нельзя надёжно различить выбранным способом опроса Windows. При таком назначении клавиатурный кикдаун отключается. Если программа управления геймпадом эмулирует клавиатурные события, они считаются клавиатурным вводом.

Профиль определяется по последнему пути профиля в текущем игровом логе, в папке игры внутри «Документов» либо в папке `American Truck Simulator` внутри пути из `-homedir`. Лог отслеживается целиком по мере роста, поэтому в долгой поездке профиль не теряется; сбрасывает его только новый или укороченный лог. Если автоматический поиск недоступен, задайте `input / controls_file` как `path_to_file/controls.sii`; относительный путь считается от этого каталога игровых данных. Назначения перечитываются примерно раз в секунду и после изменения активности/управления. Игра должна сохранить изменённое назначение, прежде чем плагин его подхватит. Лог и файл управления не изменяются.

Существующий INI можно сохранить. `input / analog_kickdown` действует как в main и по умолчанию включён. Интервал задаётся через `input / double_tap_ms`.

## Логи и диагностика

При включённой диагностике рядом с DLL создаются `plugins/road_trip_shift/status.json` и `plugins/road_trip_shift/logs/`. В игровой `game.log.txt` дополнительно попадают только сообщения жизненного цикла (запуск, перехваты, машина, назначение клавиши, настройка режима, завершение); диагностика поездки остаётся в собственных логах плагина. Это телеметрия машины, нажатий и коробки; сетевой отправки нет. Перед отправкой просмотрите файлы: игровой лог и файл `installation.json` с информацией об установке могут содержать пути к папкам на вашем компьютере.

По умолчанию логи событий и таблицы телеметрии вместе ограничены **50 МиБ**, включая файлы предыдущих версий. Длинная сессия делится на части размером до 5 МиБ, каждая таблица начинается с заголовка. При запуске и смене части удаляются самые старые завершённые файлы. Текущая часть сначала закрывается. Посторонние файлы, игровой лог и резервные копии установщика в этот лимит не входят и не удаляются. Если старые файлы удалить не получается, запись на диск прекращается, чтобы объём не рос дальше. `status.json` остаётся небольшим, поскольку перезаписывается. Отключение диагностики сохраняет уже записанные файлы и не отключает функции коробки.

- `hooks_ready` — установка перехватов; `vehicle_supported` — распознавание машины. `reader_calls` и `shadow_reads` подтверждают обращения к чтению режима. Сами по себе эти признаки не доказывают правильное поведение в поездке.
- `MEMORY source=process` записывает приватную выделенную память, текущий/пиковый рабочий набор, изменение от первого замера и число дескрипторов всего процесса ATS. Счётчики `plugin_thunk_*` отдельно учитывают активные/сохранённые блоки перехватов, выделения, освобождения и ошибки освобождения; они не измеряют все выделения CRT-кучи DLL. В CSV/status есть время и корректность замера, память процесса и блоков. По умолчанию замер раз в 10 секунд; настройка `[logging] memory_sample_ms=10000` (1000–60000 мс). Существующий INI менять не требуется. Сравнивайте повторные поездки после прогрузки по [тест-кейсам Bronco](https://github.com/SaveljevRoman/Road_Trip_Shift/blob/fix/hook-reinit-throttle-key-ci/docs/TESTING_BRONCO_RU.md).
- `INPUT_GATE` показывает причину блокировки/ожидания, физическую клавишу, свежесть SDK, газ, тормоз и состояние двойного нажатия. В CSV/status добавлены `keyboard_held`, `input_brake`, `tap_armed`, `tap_blocked`, `analog_down`, `input_gate`; в CSV также добавлен `input_sample_valid`. `KEYBOARD_BINDING` записывает физические скан-коды (W — `0011`, S — `001F`) без путей профиля.
- `GEAR_CHOICE source=game_logic` разделяет штатного кандидата и результат плагина для путей `adjacent_limited` и `direct`. Это кандидаты: после возврата из перехвата первый путь может ограничить выбор соседней ступенью. `GEAR_CHANGED source=game_telemetry` показывает реально включённую передачу. Эта диагностическая сборка не меняет штатную политику последовательных переключений.
- Поля `keyboard_binding_ready` и `input_sample_valid` в status показывают наличие назначения и свежего сигнала газа. Событие `KEYBOARD_BINDING source=controls_sii` записывает готовность без локальных путей.
- В CSV поле `input_down` заменяет `w_down` и отражает физическое состояние назначенной клавиши газа независимо от подтверждения SDK; события `THROTTLE DOWN/UP source=game_input` показывают его нажатия и отпускания. Опрашиваются только клавиши из клавиатурного назначения газа.
- `CONFIG_MODE_CHANGED source=game_setting` — изменение настройки игры, в том числе при загрузке профиля. `KICKDOWN ON/OFF source=plugin` — временный запрос плагина. При уже выбранном мощностном режиме КПП возможно `value_changed=0`.
- При выбранном Economy круиз включает временное восстановление через Normal только при отставании от текущей цели больше 3 км/ч. После включения Normal удерживается внутри этой зоны до достижения цели, затем возвращается Economy; превышения цели на 3 км/ч не требуется. Этот гистерезис относительно цели действует при её увеличении, последующей потере скорости и восстановлении после торможения ACC. Ручной газ, кикдаун, торможение, недоступный ввод, пауза или отключение круиза отменяют восстановление; после отмены снова действует граница включения. Малые изменения цели внутри зоны не включают Normal повторно. Уменьшение цели завершает восстановление, когда новая цель достигнута. Используются Normal текущей DLL с теми же перехватами и защитой круиза; High Power кикдауна имеет приоритет. Сохранённая настройка игры не меняется. Диагностика: `CRUISE_ACCEL source=plugin`, `mode_source=cruise_acceleration`, `cruise_acceleration_normal`. Отключение: `[cruise] normal_acceleration=0`.
- `CRUISE_GUARD source=cruise_load`, `cruise_guard_cap`, `cruise_guard_clamps` — защита от неудачных повышений. `effective_brake` помогает отличить торможение адаптива от недостатка тяги. `HOLD` также записывает основание: `failed_gear`, `trial=observed_upshift` (повышение, замеченное во время обучения) или `trial=engaged_gear` (передача, включённая при перезапуске обучения; только по признаку тяжёлой нагрузки), `trial_speed_kmh` (наибольшая скорость в цепочке повышений), `entry_throttle` (газ при первом повышении цепочки), `peak_throttle` и `trial_age_ms` (с последнего повышения цепочки).
- `KEYBOARD_BINDING_WORKER START`/`STOP` показывают, читаются ли `controls.sii`/игровой лог в фоновом потоке (`mode=background`) или, если поток не запустился, синхронно в потоке игры (`mode=synchronous_fallback`).
- Если перехваты не применились, проверьте лог: найдены ли сигнатуры инструкций и нет ли конфликта с другими плагинами коробки.
- Сравните одиночное нажатие газа, двойное нажатие с отпусканием и круиз при разных скоростях и нагрузках. Высшая передача сама по себе не критерий успеха: машина должна поддерживать скорость. Адаптивный круиз может снижать скорость из-за трафика.


## Штатный HUD и диагностика двигателя

В тестовой сборке PR добавлен [индикатор в штатном HUD](MODE_NOTICE_RU.md). По умолчанию: `[hud] enabled=1`, `duration_ms=2500`, `language=auto` (язык интерфейса Windows; доступны `en`/`ru`). Существующий INI остаётся действительным. Настройки видимости игровых уведомлений сохраняют действие. Ошибка UI-сигнатур отключает только индикатор; `MODE_NOTICE READY/REQUEST/EXPIRE_REQUEST` отмечает готовность/запросы, не доказывая отрисовку. Визуальная проверка в поездке ожидается.

Дополнительная диагностика двигателя добавляет в CSV поля `engine_enabled`, `motor_brake`, `parking_brake`, `electric_enabled`, `retarder_level`, `input_clutch`, `effective_clutch`, `engine_wear` и `engine_signals_valid`. Значение -1 означает недоступный сигнал, а не подтверждённое выключение/ноль. Биты маски достоверности 0–7 соответствуют этому порядку. `ENGINE_STATE source=game_telemetry` пишет начальную доступность, изменения дискретных сигналов/ретардера и переходы сцепления ноль/не ноль сразу в SDK-колбэках, с контекстом скорости, оборотов, передачи, газа и тормоза; непрерывные значения сцепления/износа сохраняются в CSV. Регистрация каналов необязательна, её ошибка не отключает коробку. При смене машины достоверность сбрасывается. Прямого признака отсечки топлива/ограничителя оборотов в SDK нет: новые сигналы помогут различить включение двигателя, торможение и сцепление, но сами по себе не докажут краткую отсечку.

## Удаление

### Замеры в наносекундах

`[logging] timing=1` по умолчанию включает замеры длительности через QPC. `timing_sample_ms=10000` задаёт интервал отчётов (1000–60000 мс); `timing_hook_every=64` — выборку штатных reader/chooser (1–4096). Существующий INI менять не нужно. Для сравнения без измерений задайте `timing=0` перед запуском; `logging/enabled=0` тоже отключает их. Длительности и добавленная в события/CSV метка `qpc_ns` выражены в наносекундах от первой инициализации QPC в загруженной DLL, а не в UTC. `qpc_ns=0` означает отключённый/недоступный замер либо начало отсчёта.

`PERF_CLOCK` показывает реальную частоту QPC и номинальный шаг счётчика. Счётчики `PERF` накопительные за время жизни загруженной DLL, включая повторную инициализацию SDK: число замеров, суммарная/средняя/максимальная длительность и количество вызовов от 100 мкс, 1 мс и 5 мс. Для перехватов считается число замеренных вызовов, не все обращения игры. Остальные разделы включают работу колбэков на паузе/в меню. `frame_start`/`frame_end` — время колбэков DLL, не полное время кадра игры/FPS. `keyboard_binding_io` (ранее `keyboard_binding`) — одно чтение и разбор игрового лога/`controls.sii`; обычно выполняется в фоновом потоке и тогда не входит в `frame_end`. Родительские замеры включают дочерние и накладные расходы, поэтому складывать их нельзя. Общий замер перехвата включает штатный reader/chooser, отдельно есть длительность самой игровой функции. Измерение тоже создаёт нагрузку, а выборка может пропустить задержку незамеренного вызова. Одни тайминги не доказывают причину переключения или медленную работу DLL.

Закройте ATS и удалите только `bin/win_x64/plugins/road_trip_shift.dll`. Папку `road_trip_shift` можно удалить, если больше не нужны настройки, логи и резервные копии. Не удаляйте общую папку `plugins`. Изменения памяти исчезают при выходе из ATS.

## Приоритет клавиатурного кикдауна

Двойное нажатие назначенной клавиши газа имеет высший приоритет выбора режима КПП: временный High Power перекрывает Off, Economy, Normal, уже выбранный High Power, пользовательские значения, удержание/восстановление круиза и обе настройки круиза. При включении кикдауна временный Normal снимается сразу и не может включиться до окончания удерживаемого кикдауна. Изменение выбранного режима игры во время удержания не прерывает High Power. Отпускание возвращает текущую политику выбора режима/восстановления, без сохранения или перезаписи настройки игры. Как в main, разгон полным газом выполняется игровым «Умным газом» и штатными картами коробки: DLL не создаёт газ и не назначает передачу по номеру. Проверки корректного ввода, поддерживаемой машины, включённого плагина и отмены сохраняются.


Актуальный состав новой ветки и отложенные функции: [план реализации](IMPLEMENTATION_PLAN.md).

CRUISE_ACCEL теперь пишет цель/скорость/ошибку с шестью знаками, номер и интервал перехода, оба вида газа/тормоза, доступность SDK, клавишу/кикдаун, scope/фокус, опцию Normal, предел защиты, передачу и RPM. Цель/скорость в CSV также имеют шесть знаков. Добавлен гистерезис: Normal включается при отставании больше 3 км/ч и выключается на цели. См. план реализации.
